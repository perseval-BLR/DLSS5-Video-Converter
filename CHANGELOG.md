# Changelog

Все изменения ниже фиксируют состояние репозитория **до** сборки exe
(`build_exe.bat`) и публикации GitHub-релиза. Дата фиксации: 2026-08-31.

## [0.1.4] — 2026-09-02

### Исправлено

- **Сервер умирал при свёрнутой вкладке** (`app.py`): Chrome/Edge троттлят
  `setInterval` в фоновых вкладках (до 1 раза в 60 c), а heartbeat-таймаут был
  30 c — сервер сам завершался, пока вкладка просто свёрнута. Симптом юзера:
  «network error» при клике на превью через минуту. Таймаут увеличен до 120 c,
  при закрытии вкладки страница шлёт `/api/exit-pending` через `sendBeacon`
  (выход через 5 c, отменяется heartbeat при перезагрузке) — автовыход
  сохранён, ложных срабатываний нет.
- **Превью грузило весь файл на сервер** (`app.py`): первый клик «Превью
  кадра» загружал исходное видео целиком (275 МБ висели минуты, кнопка
  блокировалась). Теперь браузер шлёт canvas-снимок текущего кадра
  (JPEG base64, ~50-100 КБ) — превью мгновенное, upload не нужен.
- **Превью одним изображением в размер окна видео**: убран side-by-side
  ДО/ПОСЛЕ (оригинал не показывается), результат NR — одна картинка
  шириной в колонку плеера.
- **Клампинг параметров превью**: фото-CLI принимает intensity/tone/structure
  только [0, 2], skin [-1, 2] — значения выше обрезаются, в UI показывается
  пометка «(clamped to [0,2])». Рендер работает с полными значениями.

### Добавлено

- **Самодостаточный архив**: `nvngx_dlssnr.dll` включена в `preview/` внутри
  zip — распаковал и работает, ничего дополнительно класть не нужно
  (раньше DLL копировалась при старте из `bin/runtime`).

## [0.1.3] — 2026-09-02

### Добавлено

- **Превью кадра** (кнопка «Превью кадра» под видео): выдергивает текущий кадр
  из видео (по позиции перемотки) и прогоняет его через NR Media CLI с текущими
  ползунками — ДО/ПОСЛЕ рядом. Ползунки → пере-превью с debounce 400 мс.
  **Честно: это «кое-как»-превью** — кадр обрабатывается без temporal-контекста
  (optical flow), как фото; для подбора intensity/tone/structure достаточно,
  но финальный рендер может отличаться. Полноценный live-превью в воркере —
  отдельная крупная фича (C++-патч), не сделана.
- Требует `preview/dlssnr-image.exe` + `preview/caller/nvngx.dll` в папке
  приложения (из NR Media UI); `nvngx_dlssnr.dll` копируется из `bin/runtime`
  при старте. Если файлов нет — кнопка скрыта, превью недоступно.

## [0.1.2] — 2026-09-02

### Исправлено

- **60 fps видео замедлялись до 30 fps** (`core.py`): фикс v0.1.1 жёстко
  ставил time_base 1/30, из-за чего кадры 60 fps растягивались по времени.
  Теперь time_base берётся из rate входного потока (1/rate) — исходный fps
  сохраняется, NUT-краш при этом не возвращается.

### Добавлено

- **Lossless-режим кодирования** (Quality → «Lossless (NVENC)»): `-tune lossless`
  для H.264/HEVC NVENC (yuv444p), фолбэк — libx264/libx265 `-crf 0`.
  AV1 lossless не поддерживается NVENC — при выборе будет понятная ошибка.
- **Авто-выход при закрытии браузера** (`app.py`): страница шлёт heartbeat
  каждые 5 c; если вкладок не осталось (30 c тишины) и рендер не идёт —
  процесс сам завершается. Больше не нужно убивать exe через диспетчер задач.
- **Кнопка «Выход» (⏻) в шапке**: явное завершение приложения с подтверждением.

## [0.1.1] — 2026-09-02

### Исправлено

- **Жёсткий краш NUT-мультиплексора на time_base ≠ 1/30** (`core.py`):
  промежуточный rawvideo-поток в NUT писался с time_base входного файла
  (1/1000 у mp4, 1/90000 и т.п.). На таких шкалах NUT падает при записи
  трейлера (`close`) — процесс умирает без исключения, в `jobs/` остаётся
  обрезанный `processed-video.mkv`. Симптом юзера: «программа работает
  как нужно, но заканчивает работу в рандомный момент».
  Теперь поток и кадры всегда используют time_base 1/30, PTS конвертируется
  из шкалы входного потока.
- **`Invalid argument: '!?' returned 22`** (`core.py`): PyAV `ArgumentError`
  (EINVAL) на кадрах с невалидным PTS — декодер отдаёт `None`/отрицательный/
  NOPTS, а NUT-мультиплексор падает на невалидных или обратных PTS.
  Проявлялось на кадрах после смены сцены (монтажа). Теперь PTS
  санитизируется: невалидные заменяются на следующий за последним,
  гарантируется строгая монотонность.

## [0.1.0] — 2026-08-31

Fork проекта **Merserk/dlss5-video-converter v0.1** → **DLSS 5 Video Converter**
(локальный веб-инструмент: Python `http.server`, порт 7860, биндинг только на
`127.0.0.1`; бэкенд — `dlss5_converter.core`, feature 18 + optical flow + NVENC).

### Добавлено

- **Профиль «Extreme / Overdrive»** — максимальный пресет NR (intensity 2.50,
  local tone 2.00, local structure 2.00, skin structure 1.5) в дополнение к
  Faithful / Natural / Strong / Cinematic.
- **Слайдеры NR-параметров**: Intensity, Local Tone, Local Structure — диапазон
  0–3; Skin Structure — от −1 до 3; шаг 0.05. Любое ручное значение
  переопределяет соответствующий параметр выбранного профиля.
- **Честные фазы прогресса**: отдельные стадии «анализ видео (ffprobe)» →
  «NR-конверсия кадров» → «NVENC-энкод», без фиктивных процентов.
- **RU/EN локализация** (`data-i18n`, переключатель в шапке, язык запоминается
  в localStorage).
- **Тёмная/светлая тема** (переключатель в шапке, выбор запоминается).
- **Футер с каналом автора** (YouTube @perseval_BLR).
- **README-модалка**: просмотр `README.md` / `README.ru.md` прямо в UI, язык —
  по текущей локали.
- **Папка `originals/`** — исходное видео сохраняется рядом с результатом.
- **PSNR/SSIM метрики**: сравнение оригинала с результатом по каждому 30-му
  кадру (`compute_video_metrics`, шаг 30), значения пишутся в `report.json`.
- **Сплит-сравнение**: кнопка «Сравнить» в ленте результатов — оригинал
  слева, DLSS 5 справа.

### Исправлено

- **`-shortest` / синхронизация длительности** (`core.py`):
  - MP4 — аудио дотягивается тишиной (`apad`), `-shortest` режет по видео;
  - MKV — `-shortest` убран: копия аудио/субтитров просто заканчивается
    раньше, как и положено в Matroska.

### Обновлено (из v0.1 форка)

- Профили Faithful / Natural / Strong / Cinematic с пресетами feature 18 и
  настройками ui_correction / auto_mask.
- Кодеки H.264 / HEVC / AV1 (NVENC; H.264/HEVC — фолбэк на libx264/libx265),
  контейнеры MP4 (+faststart, AAC 192 кбит/с) и MKV (копирование потоков),
  качество High / Balanced / Small (CRF 17/20/24).

### Техническое

- Портирование и доработка под standalone-вызов `nvngx_dlssnr.dll`
  (RTX 50-версия 310.8.0 в модифицированной сборке для вызова вне движка,
  ~158 MB), `nvngx.dll` — worker-образ для подписи NGX-сниппета.
- CHANGELOG зафиксирован до сборки exe и релиза.
